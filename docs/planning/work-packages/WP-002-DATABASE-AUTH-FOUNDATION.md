## 2. Purpose

Establish the complete DB + Auth foundation: PostgreSQL Neon connected via drizzle-orm/neon-http, Drizzle ORM with versioned migrations, the Offer schema (jsonb description, 4-state enum), Better Auth (Username plugin + Admin plugin + emailAndPassword with disableSignUp + database sessions + database-backed rate limiting), principalType field (ADMIN / FANTOMAS), can()/requireCapability() authorization layer, and an idempotent bootstrap script creating Fantomas + initial ADMIN — without any admin business UI, public portal, or Tiptap editor.

## 7. Intended Behavior

### Database Connection
- `lib/server/db.ts` — Drizzle client instantiated with drizzle-orm/neon-http, reading DATABASE_URL from env var
- All server-side DB access goes through this client
- No client-side DB access (server-only)

### Schema (offers table)
- `id` — uuid, primary key, default gen_random_uuid()
- `title` — text, NOT NULL
- `description` — jsonb, NOT NULL (Tiptap JSON compatible; no raw HTML)
- `status` — offer_status enum, NOT NULL, default 'DRAFT'
- `company` — text, NULL
- `sector` — text, NULL
- `category` — text, NULL
- `contract_type` — text, NULL
- `education_level` — text, NULL
- `experience` — text, NULL
- `location` — text, NULL
- `source_publication_date` — date, NULL
- `application_deadline` — date, NULL
- `source_name` — text, NULL
- `source_url` — text, NULL
- `application_modalities` — text, NULL
- `application_email` — text, NULL
- `application_url` — text, NULL
- `published_at` — timestamptz, NULL (set on first publication)
- `created_at` — timestamptz, NOT NULL, default now()
- `updated_at` — timestamptz, NOT NULL, default now()
- Indexes: idx_offers_status, idx_offers_published_at_desc (partial, WHERE status='PUBLISHED'), idx_offers_created_at_desc

### Better Auth
- Login via username + password (Username plugin signInUsername endpoint)
- No public signup (disableSignUp: true)
- Database sessions (session table managed by Drizzle adapter)
- Password hashing via scrypt (Better Auth default)
- Rate limiting via Better Auth integrated rate limiter with database storage

### Authorization
- can(principal, capability) — pure function reading principalType
- requireCapability(capability) — calls getPrincipal() + can(); throws/redirects if not authorized
- getPrincipal() — calls Better Auth getSession(), maps to Principal type (id, username, principalType)

### Bootstrap
- Run via `pnpm db:bootstrap`
- Reads FANTOMAS_INITIAL_PASSWORD from env
- Creates Fantomas (username="Fantomas", principalType="FANTOMAS") via auth.api.createUser() if not exists
- Creates initial ADMIN (from config, principalType="ADMIN") via auth.api.createUser() if not exists
- Better Auth handles password hashing (scrypt) — no manual hash INSERT
- Second run: checks existence, does NOT overwrite, logs warning

## 9. Data Semantics

### Offers Table (db/schema.ts)
- 21 fields per S6 §9.3.1
- title required (NOT NULL), description required (jsonb NOT NULL)
- All other content fields optional (NULL)
- status enum with 4 values
- published_at NULL until first publication
- created_at / updated_at system-managed (default now())
- UUID v4 primary key
- Partial index on published_at DESC WHERE status='PUBLISHED'
- No separate tables for company/sector/category (free-text per TD-021)

### Better Auth Tables
- Generated by Better Auth Drizzle adapter based on config
- user table: id, email, emailVerified, name, username (Username plugin), image, createdAt, updatedAt, principalType (V1 extension), role (Admin plugin internal)
- session table: id, expiresAt, token, userId, createdAt, updatedAt
- account table: id, userId, providerId, accountId, ... (Better Auth standard)
- verification table: id, identifier, value, expiresAt, ... (Better Auth standard)
- rate-limit table: generated by Better Auth rate limiter config

### MIGRATION REQUIRED: YES
- Purpose: create initial schema (offers + Better Auth tables + enums)
- Affected data/schema: new tables, new enums, new indexes
- Data preservation: N/A (initial migration, no existing data)
- Target: local dev/test DB only (NOT Production, NOT Preview)

## 11. Technical Boundaries

- **ADR-0001 (modular monolith):** All DB/Auth code is server-side within the monolith. No separate backend service.
- **ADR-0002 (persistence):** PostgreSQL Neon + Drizzle ORM + drizzle-orm/neon-http. No Prisma, no other ORM.
- **ADR-0003 (authentication):** Better Auth + Username plugin + Admin plugin + emailAndPassword { disableSignUp: true } + database sessions + database rate limiting + scrypt hashing.
- **ADR-0004 (authorization):** principalType + can()/requireCapability(). Better Auth role is NOT the business authorization source.
- **ADR-0006 (environment isolation):** Production ≠ Preview ≠ Local. WP-002 targets Local/dev/test DB only.
- **ADR-0007 (migrations):** Drizzle Kit + forward corrective doctrine. Never drizzle-kit push to Production.
- **ADR-0008 (testing):** Vitest + real DB in integration tests (no DB mocking).
- **TD-030 (neon-http):** drizzle-orm/neon-http (HTTP-based, no interactive transactions). No neon-serverless WebSocket, no postgres-js.
- **S0 §13:** No secrets in repository. .env.example has placeholders only.
- **S0 §25:** Target verification before any DB write (local dev/test only for WP-002).
